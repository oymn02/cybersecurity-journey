# 120-day learning roadmap

A flexible roadmap designed to fit around full-time work. The sequence prioritizes foundations, applied practice, and published evidence over collecting courses.

## Phase 1 · Baseline and setup (Days 1–15)

**Goal:** establish a reliable starting point and refresh core concepts.

- [ ] Review current knowledge of networking, Linux, HTTP, Python, and security.
- [ ] Set up a safe local learning environment.
- [ ] Create a consistent lab-note template.
- [ ] Complete an introductory web-security lab.
- [ ] Record strengths, gaps, and questions for the next phase.

**Deliverable:** baseline assessment and first complete lab write-up.

## Phase 2 · Cybersecurity foundations (Days 16–40)

**Goal:** understand the mechanics behind common security issues.

- [ ] TCP/IP, DNS, ports, routing, and TLS.
- [ ] Linux command line, users, permissions, and processes.
- [ ] HTTP requests, responses, cookies, sessions, and APIs.
- [ ] Python fundamentals for parsing, requests, and automation.
- [ ] Web vulnerabilities through authorized practice labs.

**Deliverable:** several documented labs and one small Python utility.

## Phase 3 · AI security (Days 41–70)

**Goal:** understand how AI-enabled applications fail and how to test them responsibly.

- [ ] LLM application architecture and common data flows.
- [ ] Prompt injection and indirect prompt injection.
- [ ] Sensitive information disclosure and insecure output handling.
- [ ] RAG data boundaries, retrieval risks, and access control.
- [ ] Tool-use and agent security.
- [ ] Risk analysis and practical mitigations.

**Deliverable:** an LLM security assessment with threat model, test cases, findings, and mitigations.

## Phase 4 · Engineering and portfolio (Days 71–95)

**Goal:** turn learning into reusable technical work.

- [ ] Build a small network or web-security helper in Python.
- [ ] Add safe input handling, clear errors, and usage documentation.
- [ ] Build an AI-security testing or evaluation prototype.
- [ ] Add reproducible examples and tests.
- [ ] Review every project for clarity, limitations, and safe scope.

**Deliverable:** two small, clearly documented projects.

## Phase 5 · Positioning and next steps (Days 96–120)

**Goal:** make the work legible to technical and business audiences.

- [ ] Review the portfolio for technical depth and evidence.
- [ ] Identify the largest remaining skill gaps.
- [ ] Compare relevant certifications against actual role requirements.
- [ ] Update professional positioning and project summaries.
- [ ] Select the next 90-day specialization based on demonstrated progress.

**Deliverable:** a coherent portfolio and a realistic next-step plan.

## Weekly operating rhythm

Use a repeatable rhythm rather than an ambitious daily target:

- **Learn:** one focused concept.
- **Practice:** one lab or small implementation.
- **Document:** publish what was tested, what happened, and what remains unclear.
- **Review:** choose the next smallest useful task.

The roadmap is a guide, not a deadline. Move forward when the practical work demonstrates understanding.
